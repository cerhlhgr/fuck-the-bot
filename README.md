# Telegram-бот для беседы с ИИ

Бот принимает обновления Telegram через `POST /telegram/webhook` и сразу сохраняет их вместе с сообщениями в PostgreSQL. Встроенный worker по расписанию (по умолчанию каждые 30 секунд) собирает накопившиеся сообщения отдельно для каждого чата и темы, загружает переписку за последний час и постоянную память, затем делает один запрос к GPT 5.4 Nano через Timeweb AI на каждую беседу с новыми сообщениями, в которых есть @упоминание бота или ответ на его сообщение. ИИ возвращает список действий для накопившихся просьб: ответить реплаем, написать всему чату, создать нативный опрос, прислать ссылку на картинку, поставить реакцию, упомянуть участника, запустить музыкальный трек или отправить голосовое. Если отвечать не нужно, список пуст. Адресатом реплая, реакции и голосового может быть только пользовательское сообщение из переданного контекста. Поводом для обращения к ИИ служит прямое `@упоминание` бота в тексте или подписи к фото либо ответ на сообщение бота. Остальные сообщения сохраняются как контекст, но сами по себе не запускают ИИ. `message_thread_id` считается отдельной темой только при `is_topic_message=true`: ответы в обычной супергруппе остаются в общей переписке. Если пользователь отвечает на сообщение бота, ИИ получает текст этого сообщения и ID ответа пользователя; при выборе ID старой реплики бота адрес ответа автоматически исправляется на сообщение пользователя.

Бот запоминает авторов новых сообщений в `bot_contacts`: для каждого чата хранит Telegram user ID, имя, @username (если есть), ссылку для упоминания и время последнего сообщения. Имя и username обновляются при новых сообщениях пользователя. Участники без @username также доступны для упоминания через `tg://user?id=...`. Когда просят позвать или линкануть человека, worker добавляет в запрос к ИИ до 100 недавних контактов этого чата. ИИ может сопоставить разговорное имя с сохранённым именем или @username и вернуть отдельный `mention` для каждого человека; worker проверяет каждое совпадение в полной таблице чата и отправляет Telegram-упоминание ответом на просьбу. Бот сам попросит уточнение при нескольких совпадениях или сообщит, что контакт не найден. На обычные вопросы список контактов в ИИ не передаётся. Контакты начинают накапливаться из новых обновлений после применения миграции `000007_contacts`; получение полного списка участников через Bot API не требуется.

Если в новых сообщениях есть важная информация (встреча, договорённость, правило беседы), ИИ добавляет к решению массив `important_updates`. Каждая запись содержит ID исходного сообщения и самостоятельную формулировку факта. Бот сохраняет их вместе с полными исходными сообщениями в отдельной таблице `bot_important_context`. Записи привязаны к чату и теме и не удаляются при суточной очистке. С каждым следующим запросом ИИ получает все краткие формулировки, даты, авторов и типы записей этой беседы; полные оригиналы остаются в БД и не дублируются в запросе. Массив может сопровождать любое действие, включая молчание. При явной отмене ИИ возвращает `forget_important_ids` с ID отменённых записей; бот удаляет их только в текущем чате и теме. Удаление и сохранение нескольких новых записей выполняются в одной транзакции. Неотменённые сведения остаются в памяти. Сообщения без @упоминания и без ответа на бота сохраняются в обычной истории, но сами не запускают ИИ и не пополняют постоянную память.

Прямые указания боту («не пиши», «пиши», «не создавай опросы» и подобные) сохраняются там же с типом `instruction` и временем исходного сообщения. ИИ получает их в хронологическом порядке и должен следовать последнему указанию по каждому поведению: например, сегодняшнее «пиши» в 08:00 отменяет вчерашнее «не пиши» в 20:00. При такой замене старая инструкция удаляется. Запрет писать не останавливает обработку новых сообщений — бот продолжает получать и запоминать новые указания. Записи типа `fact` сохраняют прежний смысл.

По просьбе о поиске ИИ возвращает действие `search` с запросом и типом `web`, `news`, `images` или `videos`. С ключом Brave Search API бот получает реальные результаты из соответствующего индекса и отправляет до трёх ссылок с названиями и короткими описаниями; для картинок — до двух прямых ссылок и страницы источника. Полные страницы бот не читает, а поисковые описания не считает доказательством сверх написанного в них. Если API недоступен или по картинкам нет результатов, бот пробует Wikimedia Commons. Без ключа Brave сохраняется прежний поиск картинок в Wikimedia Commons; поиск сайтов, новостей и видео отключён.

Фотографии с @упоминанием бота или в ответ на его сообщение он загружает через Telegram и кратко описывает отдельным запросом к GPT 5.4 Nano. Подпись к фото и описание доступны ИИ в контексте последнего часа, поэтому он может обсуждать фото сразу и в следующих сообщениях. Сами изображения в PostgreSQL не сохраняются. Максимальный размер выбранной версии фото — 5 МБ; если загрузка или распознавание не удались, ИИ получает пометку, что содержимое фото недоступно. Описания одинаковых по содержимому файлов кешируются в памяти процесса на сутки (не более 1024 записей), поэтому повторно присланное фото не вызывает второй запрос к модели зрения.

Ответ ИИ — один JSON-объект с массивом `actions` (до 32 элементов). Каждый элемент поддерживает `reply`, `message`, `poll`, `image`, `search`, `reaction`, `mention`, `music` или `voice`. Общие изменения постоянной памяти находятся снаружи массива. Пример:

```json
{
  "actions": [
    {"action":"reply","reply":"Привет, блин","reply_to_message_id":123},
    {"action":"poll","poll":{"question":"Куда идём?","options":["В кино","Домой"]},"reply_to_message_id":124},
    {"action":"voice","voice":{"text":"Ну что, собрались уже?","speaker":"onyx","instructions":"Говори естественно и с лёгкой ехидцей"},"reply_to_message_id":125},
    {"action":"search","search_type":"videos","search_query":"ремонт велосипеда видео","reply_to_message_id":126}
  ],
  "important_updates": [
    {"source_message_id":124,"summary":"Встреча участников 12 октября в 18:00 у главного входа.","kind":"fact"}
  ]
}
```

Для `message`, `poll` и `image` поле `reply_to_message_id` может быть `null`, тогда действие адресовано чату или текущей теме целиком. `search` привязывается к сообщению с просьбой о поиске. `{"actions":[]}` означает молчание; с пустым списком можно сохранить или отменить сведения через `important_updates` и `forget_important_ids`. Старый формат с одним полем `action` продолжает приниматься.

Если участник просит голосовое, ИИ возвращает короткий текст для озвучивания, голос и указание интонации. Бот обращается к `openai/gpt-4o-mini-tts` в Timeweb AI Gateway, получает MP3 и загружает его в Telegram как `sendVoice` в исходный чат и тему ответом на просьбу. Для этого используется уже обязательный `TIMEWEB_AI_API_KEY`, дополнительный ключ и callback не нужны. Текст ограничен 1000 символами, инструкция по голосу — 300 символами, готовый файл — 10 МБ. При ошибке синтеза бот отвечает текстом. Генерация голосового оплачивается отдельно от запроса к GPT 5.4 Nano.

## Настройка

Обязательные переменные окружения:

```dotenv
TELEGRAM_BOT_TOKEN=токен_от_BotFather
TIMEWEB_AI_API_KEY=ключ_Timeweb_AI
DATABASE_URL=postgres://user:password@host:5432/database?sslmode=require
```

Дополнительные переменные:

```dotenv
DECISION_INTERVAL=30s
LISTEN_ADDR=:8080
BRAVE_SEARCH_API_KEY=ключ_Brave_Search_API
```

`BRAVE_SEARCH_API_KEY` нужен для общего поиска в интернете. Получите его в [Brave Search API](https://brave.com/search/api/) и задайте в окружении запущенного приложения. Ключ передаётся только сервером в заголовке `X-Subscription-Token`; в чат и логи он не записывается. Каждый поисковый запрос тарифицируется Brave отдельно от запросов к GPT.

Для генерации треков добавьте все три переменные:

```dotenv
SUNO_API_URL=https://apibox.erweima.ai/api/v1
SUNO_API_SECRET_KEY=ключ_провайдера_Suno
SUNO_API_CALLBACK_URL=https://bot.example.com
```

Интеграция использует тот же API `/generate`, что и `taratorka_bot`, с моделью Suno `V6`. `SUNO_API_CALLBACK_URL` — публичный HTTPS-адрес приложения **без пути**; бот сам создаёт уникальный адрес `/suno/callback/{token}` для каждой задачи. При просьбе создать трек ИИ возвращает параметры `music` в JSON, а бот сохраняет задачу в PostgreSQL и запускает генерацию. Когда Suno присылает callback `complete`, бот сохраняет все готовые аудиотреки и отправляет их в исходный чат и тему ответом на просьбу. При ошибке отправки аудио бот пробует прислать ссылку; неотправленные треки повторяются после перезапуска. Отдельно регистрировать callback в Telegram не нужно. Если переменные Suno не заданы, действие `music` отключено.

Если Suno отклоняет создание трека, найдите в логах строку `Suno generation failed`. Она содержит адрес API без секретов, HTTP-статус, код и сообщение провайдера. Например, `HTTP 200 provider_code=401` означает ошибку авторизации: проверьте, что `SUNO_API_URL` и `SUNO_API_SECRET_KEY` в окружении **запущенного приложения** относятся к одному провайдеру. Ключ от API Box не работает на адресе Kie. В переменной должен быть сам ключ без префикса `Bearer`; бот добавляет этот префикс. Содержимое ключа в журнал не записывается.

После публикации приложения один раз зарегистрируйте его публичный HTTPS-адрес в Telegram (замените `bot.example.com` на домен приложения):

```sh
curl --request POST "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/setWebhook" \
  --data-urlencode "url=https://bot.example.com/telegram/webhook" \
  --data-urlencode 'allowed_updates=["message"]'
```

Бот сам не вызывает `setWebhook`. Хендлер слушает путь `/telegram/webhook`, но наличие хендлера не сообщает Telegram публичный адрес.

`WEBHOOK_SECRET` больше не используется. Хендлер принимает POST без проверки заголовка `X-Telegram-Bot-Api-Secret-Token`; публичную ручку может вызвать любой, кто знает её адрес. Ограничение размера тела и проверка JSON остаются.

Для запуска Go-процесса задайте переменные в окружении и выполните `go run .`. Приложение слушает HTTP на `:8080`; публичный HTTPS обеспечивает ваш reverse proxy или платформа размещения. При запуске `main.go` применяет SQL-миграции из `internal/migrations/sql/` до обработки обновлений.

Чтобы бот видел переписку группы, отключите **Group Privacy Mode** через [@BotFather](https://t.me/BotFather) или назначьте бота администратором. После изменения режима удалите бота из группы и добавьте заново. Старая история Telegram через Bot API недоступна.

## Данные и проверка

Логи пишутся в стандартный вывод и доступны в журнале приложения Timeweb. Для каждого запроса видны `webhook request received` и результат `webhook accepted` либо `webhook request rejected` / `webhook queue failed`. Обработчик пишет `update_id`, `chat_id`, этап запроса к ИИ и отправки ответа. После успешного ответа AI Gateway клиент пишет числовые `prompt_tokens`, `completion_tokens`, `total_tokens` и, если провайдер их вернул, `cache_hit_tokens` и `reasoning_tokens`. Если провайдер не вернул число токенов рассуждения, лог содержит `reasoning_tokens=unavailable`; отсутствие всего блока `usage` тоже видно в журнале. Ошибки содержат этап и причину; ключи и текст переписки в лог не выводятся.

Входящие обновления и сообщения сохраняются атомарно в `bot_updates` и `bot_history` при приёме вебхука. После перезапуска worker продолжает работу с необработанными обновлениями. За один запуск он берёт до 500 обновлений; избыток остаётся до следующего запуска. Выбранный список действий и исходные ID обновлений сохраняются в `bot_action_plans`. Действия выполняются по порядку; после временной ошибки worker продолжает сохранённый список с невыполненного пункта без повторного запроса к ИИ. Если Telegram сообщает о переезде группы в супергруппу, план для старого ID чата закрывается и больше не повторяется. Новые сообщения, поступившие во время повтора, обрабатываются следующим запуском. После выполнения списка исходные обновления отмечаются обработанными. Обработанные обновления удаляются через 48 часов; сообщения обычной истории старше 24 часов удаляются каждый час, планы действий — через 30 дней. Постоянный важный контекст не удаляется. Запрос к ИИ выполняется для каждой беседы с новыми пользовательскими сообщениями, где упомянут бот или ответили на его сообщение; несколько таких сообщений за интервал обычно требуют одного запроса. Все новые обращения к боту передаются целиком, остальные остаются в базе и могут попасть в выбранный контекст за последний час. Из предыдущего часа worker добавляет прямые сообщения для реплаев, до трёх старых реплик с совпадающими словами и до восьми последних реплик; для старой истории действует лимит 4000 символов. Постоянная память передаётся целиком в виде кратких записей. История остаётся в PostgreSQL, поэтому отдельная векторная БД и дополнительные запросы на эмбеддинги не нужны. В логах видны исходное и выбранное число сообщений. Очень длинные новые сообщения или большой постоянный контекст всё равно могут превысить лимит модели, и тогда ошибка появится в журнале.

`go test ./...` проверяет обработку обновлений и формат сообщений. Для SQL-проверки на отдельной тестовой базе задайте `TEST_DATABASE_URL`. Состояние регистрации webhook можно проверить методом Telegram `getWebhookInfo`.

# Telegram-бот для беседы с ИИ

Бот принимает обновления Telegram через `POST /telegram/webhook` и сразу сохраняет их вместе с сообщениями в PostgreSQL. Встроенный worker по расписанию (по умолчанию раз в минуту) собирает накопившиеся сообщения отдельно для каждого чата и темы, загружает переписку за последний час и постоянную память, затем делает один запрос к GPT 5.4 Nano через Timeweb AI на каждую беседу с новыми сообщениями. ИИ выбирает одно действие: промолчать, ответить реплаем, написать всему чату, создать нативный опрос, прислать ссылку на картинку, поставить реакцию, запустить музыкальный трек или отправить голосовое. Адресатом реплая, реакции и голосового может быть только пользовательское сообщение из переданного контекста. Поводом для действия может быть `@упоминание`, обсуждение бота, просьба или вопрос в беседе.

Если в новых сообщениях есть важная информация (встреча, договорённость, правило беседы), ИИ добавляет к решению массив `important_updates`. Каждая запись содержит ID исходного сообщения и самостоятельную формулировку факта. Бот сохраняет их вместе с полными исходными сообщениями в отдельной таблице `bot_important_context`. Записи привязаны к чату и теме и не удаляются при суточной очистке. С каждым следующим запросом ИИ получает все краткие формулировки, даты, авторов и типы записей этой беседы; полные оригиналы остаются в БД и не дублируются в запросе. Массив может сопровождать любое действие, включая молчание. При явной отмене ИИ возвращает `forget_important_ids` с ID отменённых записей; бот удаляет их только в текущем чате и теме. Удаление и сохранение нескольких новых записей выполняются в одной транзакции. Неотменённые сведения остаются в памяти.

Прямые указания боту («не пиши», «пиши», «не создавай опросы» и подобные) сохраняются там же с типом `instruction` и временем исходного сообщения. ИИ получает их в хронологическом порядке и должен следовать последнему указанию по каждому поведению: например, сегодняшнее «пиши» в 08:00 отменяет вчерашнее «не пиши» в 20:00. При такой замене старая инструкция удаляется. Запрет писать не останавливает обработку новых сообщений — бот продолжает получать и запоминать новые указания. Записи типа `fact` сохраняют прежний смысл.

Для картинки ИИ возвращает поисковый запрос. Бот ищет файл в Wikimedia Commons и отправляет найденную прямую ссылку в беседу. Если поиск не дал результата, бот сообщает об этом текстом. Новые ключи окружения для поиска не нужны.

Входящие фотографии бот загружает через Telegram и кратко описывает отдельным запросом к GPT 5.4 Nano. Подпись к фото и описание доступны ИИ в контексте последнего часа, поэтому он может обсуждать фото сразу и в следующих сообщениях. Сами изображения в PostgreSQL не сохраняются. Максимальный размер выбранной версии фото — 5 МБ; если загрузка или распознавание не удались, ИИ получает пометку, что содержимое фото недоступно. Описания одинаковых по содержимому файлов кешируются в памяти процесса на сутки (не более 1024 записей), поэтому повторно присланное фото не вызывает второй запрос к модели зрения.

Ответ ИИ — один JSON-объект с полем `action`. Поддерживаются `silence`, `reply`, `message`, `poll`, `image`, `reaction`, `music` и `voice`. Примеры:

```json
{"action":"reply","reply":"Привет, блин","reply_to_message_id":123}
{"action":"poll","poll":{"question":"Куда идём?","options":["В кино","Домой"]},"reply_to_message_id":123}
{"action":"image","image_query":"cat in sunglasses","caption":"Держи","reply_to_message_id":123}
{"action":"silence","important_updates":[{"source_message_id":123,"summary":"Встреча участников 12 октября в 18:00 у главного входа.","kind":"fact"}]}
{"action":"silence","important_updates":[{"source_message_id":123,"summary":"Не писать в чат до нового указания.","kind":"instruction"}]}
{"action":"silence","forget_important_ids":[123]}
{"action":"silence","forget_important_ids":[123],"important_updates":[{"source_message_id":124,"summary":"Встреча перенесена на 13 октября в 18:00.","kind":"fact"}]}
{"action":"music","music":{"mode":"simple","prompt":"весёлый панк-рок про поездку на море","instrumental":false},"reply_to_message_id":123}
{"action":"music","music":{"mode":"custom","title":"Ночной город","style":"synthpop","prompt":"[Verse] Ночной город светит огнями","instrumental":false},"reply_to_message_id":123}
{"action":"voice","voice":{"text":"Ну что, собрались уже?","speaker":"onyx","instructions":"Говори естественно и с лёгкой ехидцей"},"reply_to_message_id":123}
```

Для `message`, `poll` и `image` поле `reply_to_message_id` может быть `null`, тогда действие адресовано чату или текущей теме целиком. Старый формат JSON для текстового ответа и опроса продолжает работать.

Если участник просит голосовое, ИИ возвращает короткий текст для озвучивания, голос и указание интонации. Бот обращается к `openai/gpt-4o-mini-tts` в Timeweb AI Gateway, получает MP3 и загружает его в Telegram как `sendVoice` в исходный чат и тему ответом на просьбу. Для этого используется уже обязательный `TIMEWEB_AI_API_KEY`, дополнительный ключ и callback не нужны. Текст ограничен 1000 символами, инструкция по голосу — 300 символами, готовый файл — 10 МБ. При ошибке синтеза бот отвечает текстом. Генерация голосового оплачивается отдельно от запроса к GPT 5.4 Nano.

## Настройка

Обязательные переменные окружения:

```dotenv
TELEGRAM_BOT_TOKEN=токен_от_BotFather
TIMEWEB_AI_API_KEY=ключ_Timeweb_AI
DATABASE_URL=postgres://user:password@host:5432/database?sslmode=require
```

Дополнительные переменные:

```dotenv
DECISION_INTERVAL=1m
LISTEN_ADDR=:8080
```

Для генерации треков добавьте все три переменные:

```dotenv
SUNO_API_URL=https://api.kie.ai/api/v1
SUNO_API_SECRET_KEY=ключ_провайдера_Suno
SUNO_API_CALLBACK_URL=https://bot.example.com
```

Интеграция использует тот же API `/generate`, что и `taratorka_bot`, с моделью Suno `V6`. `SUNO_API_CALLBACK_URL` — публичный HTTPS-адрес приложения **без пути**; бот сам создаёт уникальный адрес `/suno/callback/{token}` для каждой задачи. При просьбе создать трек ИИ возвращает параметры `music` в JSON, а бот сохраняет задачу в PostgreSQL и запускает генерацию. Когда Suno присылает callback `complete`, бот сохраняет все готовые аудиотреки и отправляет их в исходный чат и тему ответом на просьбу. При ошибке отправки аудио бот пробует прислать ссылку; неотправленные треки повторяются после перезапуска. Отдельно регистрировать callback в Telegram не нужно. Если переменные Suno не заданы, действие `music` отключено.

После публикации приложения один раз зарегистрируйте его публичный HTTPS-адрес в Telegram (замените `bot.example.com` на домен приложения):

```sh
curl --request POST "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/setWebhook" \
  --data-urlencode "url=https://bot.example.com/telegram/webhook" \
  --data-urlencode 'allowed_updates=["message"]'
```

Бот сам не вызывает `setWebhook`. Хендлер слушает путь `/telegram/webhook`, но наличие хендлера не сообщает Telegram публичный адрес.

`WEBHOOK_SECRET` больше не используется. Хендлер принимает POST без проверки заголовка `X-Telegram-Bot-Api-Secret-Token`; публичную ручку может вызвать любой, кто знает её адрес. Ограничение размера тела и проверка JSON остаются.

Для запуска Go-процесса задайте переменные в окружении и выполните `go run .`. Приложение слушает HTTP на `:8080`; публичный HTTPS обеспечивает ваш reverse proxy или платформа размещения. При запуске `main.go` применяет SQL-миграции из `internal/migrations/sql/` до обработки обновлений.

Чтобы бот видел переписку группы, отключите **Group Privacy Mode** через [@BotFather](https://t.me/BotFather) или назначьте бота администратором. После изменения режима удалите бота из группы и добавьте заново. Старая история Telegram через Bot API недоступна.

## Данные и проверка

Логи пишутся в стандартный вывод и доступны в журнале приложения Timeweb. Для каждого запроса видны `webhook request received` и результат `webhook accepted` либо `webhook request rejected` / `webhook queue failed`. Обработчик пишет `update_id`, `chat_id`, этап запроса к ИИ и отправки ответа. После успешного ответа AI Gateway клиент пишет числовые `prompt_tokens`, `completion_tokens`, `total_tokens` и, если провайдер их вернул, `cache_hit_tokens` и `reasoning_tokens`. Если провайдер не вернул число токенов рассуждения, лог содержит `reasoning_tokens=unavailable`; отсутствие всего блока `usage` тоже видно в журнале. Ошибки содержат этап и причину; ключи и текст переписки в лог не выводятся.

Входящие обновления и сообщения сохраняются атомарно в `bot_updates` и `bot_history` при приёме вебхука. После перезапуска worker продолжает работу с необработанными обновлениями. За один запуск он берёт до 500 обновлений; избыток остаётся до следующего запуска. После решения ИИ обновления всей беседы отмечаются обработанными вместе. Обработанные обновления удаляются через 48 часов; сообщения обычной истории старше 24 часов удаляются каждый час. Постоянный важный контекст не удаляется. Запрос к ИИ выполняется для каждой беседы с новыми пользовательскими сообщениями, поэтому несколько сообщений за интервал обычно требуют одного запроса. Все новые сообщения передаются целиком. Из предыдущего часа worker добавляет прямые сообщения для реплаев, до трёх старых реплик с совпадающими словами и до восьми последних реплик; для старой истории действует лимит 4000 символов. Постоянная память передаётся целиком в виде кратких записей. История остаётся в PostgreSQL, поэтому отдельная векторная БД и дополнительные запросы на эмбеддинги не нужны. В логах видны исходное и выбранное число сообщений. Очень длинные новые сообщения или большой постоянный контекст всё равно могут превысить лимит модели, и тогда ошибка появится в журнале.

`go test ./...` проверяет обработку обновлений и формат сообщений. Для SQL-проверки на отдельной тестовой базе задайте `TEST_DATABASE_URL`. Состояние регистрации webhook можно проверить методом Telegram `getWebhookInfo`.
